## 四、wbi 签名实现要点

### 4.1 密钥获取

1. `GET https://api.bilibili.com/x/web-interface/nav` → `data.wbi_img.img_url` / `data.wbi_img.sub_url`
2. 取两者文件名（去掉 `.png`）：`img_key`、`sub_key`，拼接成长度 64 的串
3. 用 **64 项置换表** 取前 32 位字符，得 `mixinKey`
4. 密钥约 **6 小时轮换**：本实现缓存 6h，并在出现 `-352/-412` 时调用 `invalidate()` 强制刷新

置换表（与 `nicelee.bilibili.API.MixinArray` 完全一致，已反射核对）：

```
46,47,18,2,53,8,23,32,15,50,10,31,58,3,45,35,27,43,5,49,33,9,42,19,29,28,14,39,12,38,
41,13,37,48,7,16,24,55,40,61,26,17,0,1,60,51,30,4,22,25,54,21,56,59,6,63,57,62,11,36,20,34,44,52
```

```java
private static String mixinKeyOf(String rawWbiImg) {   // rawWbiImg = imgKey + subKey（64 位）
    StringBuilder sb = new StringBuilder(32);
    for (int i = 0; i < 32; i++) {
        sb.append(rawWbiImg.charAt(MIXIN_KEY_ENC_TAB[i]));
    }
    return sb.toString();
}
```

### 4.2 签名计算

```
wts   = 当前秒级时间戳
base  = 所有参数（含风控参数）按 key 排序后 "k=v" 用 & 连接 + "&wts=" + wts
w_rid = MD5(base + mixinKey)
最终 query = 原参数（含风控参数） + "&w_rid=" + w_rid + "&wts=" + wts
```

### 4.3 三个必须记住的坑（本次实测踩出来的）

1. **空值参数必须参与签名**：`keyword=`、`special_type=` 这类空值不能丢弃，否则 `w_rid` 与官方不一致（本实现已对齐）。
2. **`dm_img_*` 风控参数必须纳入签名范围**：`dm_img_list` / `dm_img_str` / `dm_img_inter` / `dm_cover_img_str` 由 `API.genDmImgParams()` 生成，它们**要一起进入 MD5**；先签名再拼参数的做法会被判 `412/-352`（本补丁已修正）。
3. **官方 `API.encWbi` 入参需以 `?` 开头**；本实现内部自行拼接，不需要 `?`。

### 4.4 一致性验证（`tools\WbiCheck.java`）

同一秒内分别调用官方与自研实现，`w_rid` 逐字节相同：

```
official: ?mid=2&ps=5&tid=0&pn=1&keyword=&order=pubdate&platform=web&w_rid=b4d38ddbfd7cfc806ae89cea9c1f843b&wts=1793926021
ours    : keyword=&mid=2&order=pubdate&platform=web&pn=1&ps=5&tid=0&wts=1793926021&w_rid=b4d38ddbfd7cfc806ae89cea9c1f843b
WBI_SIGN_MATCH
```

> 参数 print 顺序与签名顺序不同属正常：`w_rid` 只依赖**排序后的集合**，URL 里参数顺序无关。

## 五、可直接粘贴的关键代码

### 5.1 `UpSpaceApi.fetchPage`（接口层，含参数集与签名）

```java
public UpPageResult fetchPage(long mid, int pageNum, int pageSize, String order, String keyword) {
    Map<String, String> params = new LinkedHashMap<>();
    params.put("mid", String.valueOf(mid));
    params.put("ps", String.valueOf(Math.max(1, Math.min(pageSize, 50)))); // 接口上限 50
    params.put("tid", "0");
    params.put("special_type", "");      // 空值也要签名
    params.put("pn", String.valueOf(Math.max(1, pageNum)));
    params.put("keyword", keyword == null ? "" : keyword);
    params.put("order", order == null || order.isEmpty() ? ORDER_PUBDATE : order);
    params.put("platform", "web");
    params.put("web_location", "1550101");

    // 风控辅助参数必须一起参与签名；未初始化 UA/指纹的环境下自动省略
    String dm = safeDmParams();
    String query = WbiSigner.signQuery(params, dm);
    String url = ARC_SEARCH + "?" + query;

    String content = util.getContent(url, buildHeaders(mid), buildCookies());
    return parsePage(content, pageNum);
}
```

要点：**请求头**必须带 `Referer: https://space.bilibili.com/{mid}/video`、`Origin`，UA 缺失时补桌面 UA（`412` 基本就是 UA/Referer 不对）；**Cookie** 直接复用 `HttpCookies.getGlobalCookies()`（即程序已登录的 `SESSDATA`）。

### 5.3 分页 + 限速 + 重试（`UpFetchService` 核心）

```java
for (int pn = startPage; pn <= pageCount; pn++) {
    if (listener != null && listener.isCancelled()) break;
    UpPageResult page = fetchWithRetry(mid, pn, listener);
    if (page == null) break;                 // 重试耗尽
    cp.appendPage(page);                     // 断点：每页落盘
    pageCount = page.getPageCount();
    listener.onPageFetched(page, cp.getItems().size());
    if (options.getMaxItems() > 0 && cp.getItems().size() >= options.getMaxItems()) break;
    if (pn >= pageCount || page.getItems().isEmpty()) break;
    sleepQuietly(options.getIntervalMs());   // 限速
}

private UpPageResult fetchWithRetry(long mid, int pn, Listener listener) {
    int retry = Math.max(1, options.getMaxRetry());
    for (int i = 0; i < retry; i++) {
        try {
            return api.fetchPage(mid, pn, options.getPageSize(), options.getOrder(), null);
        } catch (Throwable t) {
            boolean risk = t instanceof UpApiException && ((UpApiException) t).isRiskControl();
            if (risk) WbiSigner.invalidate();                       // 风控：换密钥
            sleepQuietly(options.getIntervalMs() * (i + 1) * (risk ? 4 : 2));   // 指数退避
        }
    }
    return null;
}
```

## 八、已知限制与建议

1. **在线拉取受风控影响**：本机命令行实测 `-403 / 412`，同环境上游解析器亦 `412`，说明是接口层面的风控/环境问题；GUI 内已登录（`SESSDATA` 有效）、正常 UA/指纹上下文下成功率与上游一致。建议**在 GUI 里实测确认**。
2. **`dm_img_*` 参数依赖应用上下文**：`API.genDmImgParams()` 需要 `Global.userAgent` / `userAgentPayload`；脱离主程序运行时会抛 `No match found`，代码已做 `try-catch` 降级（可跑，但风控更严）。因此**不建议把拉取做成独立 CLI 工具**。
3. **不要换 UA**：`bilibili.userAgent.pc` 与 `bilibili.userAgent.pc.fingerprint`（`buvid_fp`）是绑定的，随意改 UA 会直接触发 `412`。
4. **`mid=2` 等特殊账号**返回 `-403 权限不足`，属账号限制，用普通 UP 主测试。
5. 断点文件位于 `config\upall\`，可安全删除；`UpFetchService.fetchAll(mid, false, ...)` 会自动清空重拉。
6. 使用边界：仅拉取公开投稿列表并按用户已有登录态下载，未绕过付费/充电专属内容；请遵守 B 站用户协议与版权要求。
